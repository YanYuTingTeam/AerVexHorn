# ServerShout message security and resource limits

With the default empty `servershout.hmac-key`, AerVexHorn accepts the existing unauthenticated v2/v3 protocol. Use this mode only behind a ServerShout proxy that intercepts client `servershout:cast` packets, and restrict direct access to the backend to trusted proxies. The backend cannot tell a forwarded proxy message from a client message by the carrier player alone.

For authenticated operation, configure an independently generated, secret 32-byte key as exactly 64 hexadecimal characters in `servershout.hmac-key` on every receiving backend and as `hmac-key` in `shout-display-auth.properties` in the ServerShout proxy data folder. Protect the config files and keep backend and proxy clocks synchronized. Non-empty invalid keys disable AerVexHorn. With a key configured, it accepts only signed v4 messages: old v2/v3 messages are rejected, so both ends must be upgraded and configured together. Do not share the key with players. After restart, replay state is lost, so a captured valid packet can be replayed until its timestamp expires.

V4 wire format is big-endian: byte version 4, byte type (1 broadcast, 2 directed), long Unix milliseconds, two longs for a unique random UUID nonce, for type 2 a Java modified-UTF target UUID, followed by modified-UTF channel name and text. Append a 32-byte HMAC-SHA256 over all preceding bytes, using the decoded 32-byte key. Timestamps may differ by at most 60 seconds; nonce reuse is rejected for the entire timestamp validity window. A full replay cache causes new signed messages to be rejected until entries expire.

By default incoming packets are limited to 2048 per carrier and 4096 globally per second. Messages must contain 1–512 UTF-16 code units and at most eight lines; other control characters are rejected. These values are configurable under `limits` and should be sized for the expected proxy fan-out and server capacity. Each player's queue holds at most 20 messages, and overflow is discarded. These hard limits can drop bursts of otherwise legitimate messages. Window dimensions are clamped to 4096 by 2160 before creating the background image, and at most 64 size-specific images are cached.

`mvn test` runs the security and layout checks, including an independent HMAC vector, replay and timestamp checks, invalid keys, rate limits, and text bounds. Full proxy/backend/client integration testing is still required.
